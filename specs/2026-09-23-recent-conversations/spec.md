# Spec: 最近会话列表

- 状态: 已完成
- 日期: 2026-09-23
- 提出者: 用户

## 背景

客户端已经能建会话、带 `conversation_id` 续聊、按 id 拉某一通历史。但没有「最近聊过哪些」的列表，侧边栏只能靠前端自己记 id。刷新或换浏览器后无法点选旧会话继续聊。

## 目标

完成后必须满足：

- [x] 可分页查询本机最近有过消息的会话列表
- [x] 每条含 `conversation_id`、标题（首条用户消息）、最后更新时间、最后一条预览，够侧边栏展示
- [x] 客户端点选后，用原 `conversation_id` 拉历史并继续 `POST /v1/llm/chat`，记忆不断
- [x] 现有创建 / 单条历史 / 聊天接口行为不变

## 非目标

- 不做登录用户隔离；本期仍是进程内全量会话（与现有一致）
- 不做删除、置顶、重命名
- 不做跨会话搜索、向量检索
- 不改聊天记忆截断与流式协议
- 不改文生图 / 视频链路

## 用户场景

1. 作为前端，我打开聊天页时拉最近会话列表，以便侧边栏展示「之前聊过什么」。
2. 作为用户，我点击其中一条，以便回填气泡并接着问，模型仍记得上文。
3. 作为前端，我只想看到真正聊过的会话，空会话不占列表。

## 需求

### 必须

- `GET /v1/llm/conversations`：按最后一条消息时间倒序返回最近会话
- 查询参数 `limit`（默认 20，最大 50）
- 列表项包含：`conversation_id`、`title`、`created_at`、`updated_at`、`last_role`、`last_content`（截断预览）、`message_count`
- 没有消息的空会话不出现在列表中
- 点选后续聊：仍走现有 `GET /v1/llm/conversations/{id}` + `POST /v1/llm/chat`（带同一 `conversation_id`）

### 可选

- `offset` 翻页（本期用 `limit` 即可，默认只要最近一页）

## 约束与边界

- 架构：API → Service → ConversationStore Port；路由不直连 SQLite
- API：新增列表契约；`GET /{id}` 保持不变
- 安全：不返回密钥；预览截断，避免把整段长回复打进列表
- 兼容：无登录，列表是该服务实例上的全部非空会话。本地联调够用；生产若要按用户隔离需另开方案
- 存储：用现有 SQLite 表计算 `updated_at` / 标题，不强制加列

## 验收标准

- [x] 两个会话各聊一轮后，列表按更新时间倒序返回，标题来自首条 user
- [x] 刚创建、尚未发言的会话不出现在列表
- [x] 用列表里的 `conversation_id` 再聊一轮，历史能带上上一轮
- [x] `pytest` 全绿，测试不打真实外网

## 开放问题

- 无（默认 `limit=20`；空会话不进列表；不按用户过滤）
